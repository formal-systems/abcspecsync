Three checks, and what each one compares

  • These views compare names and sets, on the two files: every variable has a field, every action has a step, the guards carry the text of the enabling conjuncts, the fields that a step writes are the variables that the action primes, the frame is the same on both sides. They cannot see whether ++clock_[p] computes clock[p] + 1.
  • Trace validation compares values, on the runs that were recorded: the program writes every step and the state it produced, and TLC accepts the run only if the specification can take the same steps through the same states.
  • Model checking verifies the properties (mutual exclusion, the order of grants, progress) on every behaviour of the specification, for the constants of a model. It says nothing about the code; the first two checks are what connects it to the code.
